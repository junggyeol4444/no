0. 이 문서 사용법
--------------------------------------------------------------------
  0-1. 이 문서는 기획안이 아니라 구현 명세다.
       기획안(v0.8)은 배경 자료다. 구현할 때는 이 문서를 따른다.
       두 문서가 충돌하면 이 문서가 우선한다.

  0-2. 범위는 P0 + P1뿐이다.
       브리딩, 진화, 필드, 맵, 포획, 스토리, UI 그래픽, 오디오 곡,
       168종, 120스킬은 이 문서 범위 밖이다. 만들지 않는다.
       "나중에 필요할 것 같아서" 미리 만드는 것도 금지한다.

  0-3. 명세에 없는 기능은 추가하지 않는다.
       필요하다고 판단되면 코드를 짜지 말고 질문한다.

  0-4. P1의 목표는 게임을 만드는 게 아니라 질문 하나에 답하는 것이다.
       "되돌이가 재미있는가."
       이 질문에 답하는 데 필요 없는 모든 것은 만들지 않는다.

  - C99는 콘솔 SDK 이식성이 가장 넓다

  - raylib 외 서드파티 라이브러리 추가 금지
  - C++ 문법 사용 금지 (파일 확장자 .c만)
  - 동적 할당은 초기화 시점에만. 게임 루프 중 malloc/free 금지
  - 부동소수점 연산 금지 (3장 참조)

3. 철칙 5개  ※ 위반 시 그 커밋은 무효다
====================================================================

  철칙 1 — core/ 는 raylib을 모른다
    src/core/ 아래 어떤 파일도 raylib.h 를 include 하지 않는다.
    화면·입력·소리가 필요하면 platform.h 의 함수를 호출한다.
    이유: 콘솔 이식 시 platform_*.c 하나만 새로 쓰면 되게 하기 위함.
    검사: CI에서 `grep -r "raylib.h" src/core/` 결과가 비어야 한다.

  철칙 2 — 부동소수점을 쓰지 않는다
    float, double 타입을 게임 로직에 쓰지 않는다.
    모든 계산은 정수다. 배율은 분자/분모 쌍으로 표현한다.
    이유: 플랫폼 간 재현성. 골든 테스트가 성립하려면 필수.
    검사: CI에서 `grep -rn "\bfloat\b\|\bdouble\b" src/core/ src/data/`
          결과가 비어야 한다.
    예외: platform/ 레이어의 렌더링 좌표는 float 허용.

  철칙 3 — 모든 무작위는 명시적 시드에서 나온다
    전역 rand() 사용 금지. srand() 사용 금지.
    RNG 상태는 항상 인자로 전달한다.
    이유: 같은 시드 + 같은 입력 = 항상 같은 결과여야 한다.

  철칙 4 — 매직넘버 금지
    숫자 리터럴은 config.h 에 이름 붙여 정의한다.
    예외: 0, 1, 2 같은 자명한 값과 비트 마스크.

  철칙 5 — 명세 밖 기능 금지
    이 문서에 없는 기능을 구현하지 않는다.
    필요하다고 판단되면 코드 대신 질문을 남긴다.

4. 결정론 규칙
====================================================================

4-1. RNG 알고리즘
  PCG32 를 사용한다. 구현은 직접 작성한다 (약 30줄).

    typedef struct { uint64_t state; uint64_t inc; } Rng;

    void  rng_seed(Rng* r, uint64_t seed, uint64_t seq);
    uint32_t rng_next(Rng* r);                 // [0, 2^32)
    uint32_t rng_range(Rng* r, uint32_t n);    // [0, n), 편향 제거
    bool  rng_chance(Rng* r, uint32_t num, uint32_t den); // num/den 확률

  rng_range 는 modulo 편향을 제거해야 한다 (rejection sampling).

4-2. 스트림 분리
  용도별로 독립된 Rng 인스턴스를 둔다. 서로 영향을 주지 않아야 한다.

    RNG_BATTLE    전투 판정 (급소, 난수, 명중, 상태이상)
    RNG_ENCOUNTER 야생 조우·개체 생성
    RNG_BREED     브리딩 (P2 이후)

  이유: 전투에서 난수를 하나 더 뽑았다고 브리딩 결과가 바뀌면
        테스트가 성립하지 않는다.

4-3. 재현 가능성 요구사항
  (초기 상태 + 시드 + 입력 시퀀스) 가 같으면
  전투 로그가 바이트 단위로 같아야 한다.

  이것이 골든 테스트의 전제이며, P1의 핵심 산출물이다.

5-1. 개체 (Monster) — 정확히 34바이트, 리틀 엔디언

  오프셋 크기 필드            설명
  ──────────────────────────────────────────────────────────
   0     2   instance_id     개체 고유 ID (u16). 0 = 빈 슬롯
   2     2   species_id      종 ID (u16)
   4     2   nickname_index  별명 문자열 인덱스 (u16). 0 = 없음
   6     1   level           레벨 (u8) 1~150
   7     3   exp             누적 경험치 (u24)
  10     6   genes           유전자. 6바이트 (5-2 참조)
  16     2   nature_ability  성격 4bit + 특성 6bit + 플래그 6bit
  18     8   moves           스킬 4개 × (move_id u8, pp u8)
  26     2   cur_hp          현재 HP (u16)
  28     1   status          상태이상 3bit + 카운터 5bit
  29     1   friendship      친밀도 (u8) 0~255
  30     4   parents         부모 개체 ID 2개 (u16 × 2). 0 = 야생

  nature_ability 비트 배치 (u16, 리틀 엔디언)

    bit 4-9    특성 (0~63)
    bit 10     성별 (0 = 수, 1 = 암)
    bit 11     변이체 여부
    bit 12     유전자 검사 완료 여부
    bit 13     알 상태 여부
    bit 14-15  예약 (0으로 고정)

  status 비트 배치 (u8)
    bit 0-2    상태이상 종류
               0 = 없음 / 1 = 화상 / 2 = 마비 / 3 = 독

    구조체를 그대로 fwrite 하지 말고, 직렬화 함수를 별도로 만든다.

      void monster_deserialize(Monster* m, const uint8_t in[34]);
    저장 파일 호환성은 이 두 함수로만 보장한다.

5-5. 유전자 조건 (1바이트)

5-6. 상성표 (16바이트)
  8 × 8 = 64칸, 칸당 2bit

    값 0 = ×0.0 / 1 = ×0.5 / 2 = ×1.0 / 3 = ×2.0

    uint8_t typechart[16];
    // index = attack_type * 8 + defend_type
    // byte  = index / 4, shift = (index % 4) * 2

  P1 데이터 (타입 4개만 사용: 0=화, 1=수, 2=목, 3=토)
    화 → 목 3, 수 1, 토 1
    수 → 화 3, 토 3, 목 1
    목 → 토 3, 수 3, 화 1
    토 → 목 1, 수 1
    나머지 전부 2 (×1.0)

  ※ 타입 인덱스 전체 (P5에서 확장)
    0 화 / 1 수 / 2 목 / 3 토 / 4 금 / 5 뇌 / 6 광 / 7 암

6. 핵심 알고리즘 — 정수 연산 의사코드
====================================================================

  아래 코드는 그대로 구현한다. 연산 순서를 바꾸지 않는다.
  순서를 바꾸면 정수 나눗셈 결과가 달라져 골든 테스트가 깨진다.

6-1. 개체값 파생
    int iv_normal(uint8_t gene_byte) {
        int dom = GENE_DOM(gene_byte);
        int rec = GENE_REC(gene_byte);
        return dom * 2 + (dom == rec ? 1 : 0);      // 0~31
    }

    int iv_awakened(uint8_t gene_byte) {
        int dom = GENE_DOM(gene_byte);
        int rec = GENE_REC(gene_byte);
        return rec * 2 + (dom == rec ? 1 : 0);      // 0~31
    }

6-2. 스탯 계산
    성격 보정은 10분모 정수로 표현한다: 9 / 10 / 11

    int calc_hp(int base, int iv, int level) {
        return (2 * base + iv) * level / 100 + level + 10;
    }

    int calc_stat(int base, int iv, int level, int nature_num) {
        int v = (2 * base + iv) * level / 100 + 5;
        return v * nature_num / 10;        // nature_num: 9, 10, 11
    }

  성격 테이블 (12종, 인덱스 0~11)
    각 성격은 (상승 능력치 인덱스, 하락 능력치 인덱스) 쌍이다.
    능력치 인덱스 1=공격 2=방어 3=특공 4=특방 5=스피드 (HP=0은 제외)

     0 용맹  상승 1  하락 3
     1 저돌  상승 1  하락 2
     2 완고  상승 1  하락 4
     3 대담  상승 2  하락 1
     4 견실  상승 2  하락 3
     5 온순  상승 3  하락 2
     6 냉정  상승 3  하락 5
     7 신중  상승 4  하락 3
     8 침착  상승 4  하락 5
     9 성급  상승 5  하락 2
    10 활발  상승 5  하락 4
    11 명랑  상승 5  하락 1

    해당 능력치가 상승 대상이면 11, 하락 대상이면 9, 아니면 10

6-3. 데미지 계산
    배율은 전부 (분자, 분모) 쌍으로 순차 적용한다.
    각 단계마다 정수 나눗셈으로 절삭한다.

    int calc_damage(const BattleMon* atk, const BattleMon* def,
                    const Move* mv, Rng* rng, DamageInfo* out)
    {
        if (mv->power == 0) return 0;

        int a, d;
        if (move_class(mv) == CLASS_PHYSICAL) {
            a = atk->stat[STAT_ATK];
            d = def->stat[STAT_DEF];
        } else {
            a = atk->stat[STAT_SPA];
            d = def->stat[STAT_SPD];
        }

        // 1) 기본식
        int dmg = 2 * atk->level / 5 + 2;
        dmg = dmg * mv->power;
        dmg = dmg * a;
        dmg = dmg / d;
        dmg = dmg / 50;
        dmg = dmg + 2;

        // 2) 자속 ×3/2
        if (has_type(atk, move_type(mv))) {
            dmg = dmg * 3 / 2;
            out->stab = true;
        }

        // 3) 상성 — 배율을 4분모로 표현
        //    typechart 값 0,1,2,3 → 0/4, 2/4, 4/4, 8/4
        int eff_num = 4;
        eff_num = eff_num * eff_table[chart_get(mv_type, def->type1)] / 4;
        if (def->type2 != TYPE_NONE)
            eff_num = eff_num * eff_table[chart_get(mv_type, def->type2)] / 4;
        //    eff_table = { 0, 2, 4, 8 }
        dmg = dmg * eff_num / 4;
        out->effectiveness = eff_num;   // 0, 1, 2, 4, 8, 16, 32 형태
        if (eff_num == 0) return 0;

        // 4) 급소 1/16 확률, ×3/2
        if (rng_chance(rng, 1, CRIT_RATE_DEN)) {
            dmg = dmg * 3 / 2;
            out->crit = true;
        }

        // 5) 상태 보정 — 화상 시 물리 ×1/2
        if (atk->status_type == STATUS_BURN &&
            move_class(mv) == CLASS_PHYSICAL) {
            dmg = dmg / 2;
        }

        // 6) 난수 85~100
        int r = 85 + (int)rng_range(rng, 16);
        dmg = dmg * r / 100;

        // 7) 하한
        if (dmg < 1) dmg = 1;
        return dmg;
    }

  주의
    - 3)에서 eff_num 을 두 번 곱할 때 중간 나눗셈 순서를 바꾸지 않는다
    - 6)의 난수는 반드시 마지막에 뽑는다. 위치를 바꾸면 시드 소비가
      달라져 골든 테스트가 깨진다
    - 데미지가 0이 되는 유일한 경우는 상성 무효(3)뿐이다

6-4. 명중 판정
    P1에서는 능력 변화 단계가 없으므로 단순하다.

    bool check_hit(const Move* mv, Rng* rng) {
        if (mv->accuracy > 100) return true;          // 필중
        return rng_range(rng, 100) < mv->accuracy;
    }

6-5. 되돌이 판정
    턴 종료 시(턴 진행 7단계) 양쪽 모두에 대해 검사한다.

    void check_awaken(BattleMon* m, BattleLog* log) {
        if (m->awakened) return;
        if (m->cur_hp == 0) return;
        if (m->ability == ABILITY_REFUSE_RETURN) return;  // 회귀거부

        int threshold_num = AWAKEN_THRESHOLD_NUM;   // 기본 1
        int threshold_den = AWAKEN_THRESHOLD_DEN;   // 기본 4  (= 25%)
        // 특성 보정
        if (m->ability == ABILITY_EARLY_RETURN) {   // 조기회귀 40%
            threshold_num = 2; threshold_den = 5;
        } else if (m->ability == ABILITY_LATE_RETURN) { // 만성회귀 15%
            threshold_num = 3; threshold_den = 20;
        }

        if (m->cur_hp * threshold_den > m->max_hp * threshold_num)
            return;

        // 발동
        int old_max = m->max_hp;
        m->awakened = true;
        recalc_stats(m);                 // iv_awakened 로 재계산
        int new_max = m->max_hp;

        // 현재 HP 비율 보존. 최소 1 보장
        int new_cur = m->cur_hp * new_max / old_max;
        if (new_cur < 1) new_cur = 1;
        if (new_cur > new_max) new_cur = new_max;
        m->cur_hp = new_cur;

        log_awaken(log, m, old_max, new_max);
    }

  규칙 재확인
    - 전투당 1회. awakened 플래그는 되돌아가지 않는다
    - 교체해서 나갔다 들어와도 유지
    - HP를 회복해 임계를 넘겨도 유지
    - 전투 종료 시 플래그 해제 (개체 데이터에는 저장되지 않음)
    - 상태이상은 유지된다
    - 되돌이 발동 자체로는 턴을 소비하지 않는다

6-6. 스탯 재계산
    void recalc_stats(BattleMon* m) {
        const Species* sp = species_get(m->species_id);
        for (int i = 0; i < 6; i++) {
            int iv = m->awakened ? iv_awakened(m->genes[i])
                                 : iv_normal(m->genes[i]);
            if (i == STAT_HP) {
                m->max_hp = calc_hp(sp->base_stats[i], iv, m->level);
            } else {
                m->stat[i] = calc_stat(sp->base_stats[i], iv,
                                       m->level, nature_num(m, i));
            }
        }
    }

6-7. 턴 진행 순서
    1) 양측 행동 선택 (P1은 스킬 사용만)
    2) 우선도 비교 (높은 쪽 먼저)
    3) 동일 시 스피드 비교
    4) 동일 시 rng_range(rng, 2)
    5) 선공 실행 → 후공 실행 (선공으로 기절하면 후공 생략)
    6) 턴 종료 효과 (화상·독 지속 데미지, 상태 카운터 감소)
    7) 되돌이 판정 (양쪽)
    8) 기절 처리

  ※ 5)에서 행동 실행 도중 HP가 25% 아래로 떨어져도
    되돌이는 7)에서만 발동한다. 즉 맞은 그 턴에는 발동하지 않고
    다음 턴부터 적용된다. 이건 의도된 설계다
    [검증필요] 즉시 발동이 더 재미있을 수 있다. P1에서 둘 다 시험한다

9-1. 단위 테스트

    - rng_range 분포 편향 검사 (n=3, 100만회, 각 구간 33.3% ±0.5%)

  test_stats.c
    아래 고정 케이스가 정확히 일치해야 한다.
    (종족값 base, 유전자, 레벨, 성격 → 기대 스탯)

    케이스 A  base=60, 우성=10, 열성=10, Lv=50, 성격 보정 없음
      iv_normal   = 10*2 + 1 = 21
      calc_stat   = ((2*60 + 21) * 50 / 100 + 5) * 10 / 10
                  = (141 * 50 / 100 + 5)
                  = (70 + 5) = 75
      기대값 75

    케이스 B  base=45, 우성=7, 열성=3, Lv=50
      iv_normal   = 14
      calc_hp     = (2*45 + 14) * 50 / 100 + 50 + 10
                  = 104 * 50 / 100 + 60 = 52 + 60 = 112
      기대값 112

    케이스 C  케이스 B와 같은 개체, 되돌이 상태
      iv_awakened = 3*2 + 0 = 6
      calc_hp     = (90 + 6) * 50 / 100 + 60 = 48 + 60 = 108
      기대값 108
      → 되돌이로 최대 HP가 줄어드는 케이스. HP 비율 보존이 동작해야 함

    ※ 위 계산은 명세대로 손으로 푼 값이다.

11. 코딩 규칙
====================================================================

  파일
    - 파일당 500줄을 넘으면 분리한다
    - 헤더에는 선언만. 구현은 .c 에만
    - 헤더 가드는 #pragma once 대신 include guard 매크로

  이름
    - 타입      PascalCase   (Monster, BattleState)
    - 함수      snake_case   (calc_damage, rng_next)
    - 상수      UPPER_SNAKE  (AWAKEN_THRESHOLD_NUM)
    - 정적 함수 앞에 static 명시

  메모리
    - 동적 할당은 초기화 시점에만
    - 게임 루프 중 malloc/free 금지
    - 고정 크기 배열 우선. 크기는 config.h 에 정의

  에러 처리
    - 로더·파일 IO는 실패를 반환값으로 알린다
    - assert 는 개발 빌드에서만. 릴리스에서 로직에 의존하지 않는다

  주석
    - 무엇을 하는지가 아니라 왜 그렇게 했는지를 쓴다
    - 명세 절 번호를 참조한다. 예: /* SPEC 6-3 (3) 상성 */

12. 에이전트 작업 규칙
====================================================================

  12-1. 티켓 단위로 작업한다
    한 번에 티켓 하나. 티켓 완료 조건을 만족시키고 커밋한다.
    여러 티켓을 한 커밋에 몰아넣지 않는다.

  12-2. 각 커밋 전에 확인한다
    빌드 성공 / 전체 테스트 통과 / 정적 검사(9-3) 통과

  12-3. 명세와 다르게 구현하고 싶으면 멈춘다
    코드를 짜지 말고 이유를 적어 질문한다.
    "명세가 틀린 것 같다"고 판단해도 임의로 고치지 않는다.

  12-4. 명세에 없는 값이 필요하면 멈춘다
    임의로 정하지 않는다. 예: 종족값, 스킬 위력, 임계값.
    이 문서에 있는 값만 쓴다.

  12-5. 테스트를 통과시키려고 테스트를 고치지 않는다
    구현이 틀렸을 가능성을 먼저 검토한다.
    9-1의 손계산 케이스는 명세의 일부다. 이 값이 기준이다.

  12-6. 진행 상황을 기록한다
    PROGRESS.md 에 티켓별 완료 여부와 발견한 문제를 남긴다.

  12-7. 커밋 메시지 형식
    [T1-3] 스탯 계산 구현
    - 6-1, 6-2, 6-6 구현
    - test_stats.c 케이스 A/B/C 통과
